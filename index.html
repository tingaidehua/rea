MANIFESTO

理念：三条红线，违反任何一条即叫停

逆向是为功能性复刻服务，不是目的。功能思想不受著作权保护——我们复刻的是"它能做什么"，不是"它怎么写"。

01

只做功能语义复刻

复刻的是"它能做什么、交互流程是什么"：功能清单、交互步骤、输入输出边界。从零重写实现，不照抄任何现有实现。

02

绝不用原软件源码 / 反编译产物

反编译只用于理解功能边界与模块切分，绝不复制实现细节。注意：把原代码喂给 AI 改写后再用，不改变著作权链条，同样禁止。

03

不照搬商标与视觉资产

商标、logo、品牌名、图标、字体、滤镜预设、贴纸包、宣传文案——全部原创或合法授权，并登记进 ATTRIBUTION.md。

SHARING

共享机制：零服务器，各跑各的 key

一个人的 token 和算力是有限的——所以我们不建中心，只建广场。

🖥 零服务器

本站是纯静态站，托管在 GitHub Pages。没有后端、没有数据库、没有运维账单——本站自己就是"去中心化"这个理念的第一个实例。

🗂 协作面 = GitHub

协作靠 GitHub org + 每个软件一个公开仓库。parity.md 是进度真相源，PR 是协作语言，issue 是认领通道。不需要任何自建平台。

📦 中心只共享四样东西

prompts 模板、复刻总纲 SOP、评测集、parity 清单与算法注册表。沉淀的是可复用的资产，不是算力。

⚠️ 不搞中央 key 池

token / 算力去中心化、各跑各的 key。中央 key 池是安全和合规的坑：泄露面、滥用、账单纠纷，碰一条就死。红线，不讨论。

你（本地 key + 算力） ⇄ GitHub org（公开仓库群） ⇄ 他（本地 key + 算力）
中心流转的只有代码、文档与评测集 —— 没有 key，没有算力，没有服务器

FAQ

常见问题

这违法吗？

功能思想不受著作权保护，是各国通行的原则。著作权保护的是表达（代码、界面、文案、素材），不保护功能创意与交互流程。clean-room（只观察公开行为、从零重写）是行业成熟实践：LibreOffice 对 Microsoft Office、GIMP 对 Photoshop 都是先例。

真正的风险点有两处：① 反编译时绕过 DRM / 破解付费与会员校验；② 照搬图标、字体、滤镜预设等视觉资产。所以三红线是强制的，每个 Case 上线前做一次正式法务 review。

本站内容不构成法律意见。

卡片上的"待认领"和"待核实"是什么意思？

"待认领"：该目标尚无对应的开源功能性复现，欢迎认领开干——点卡片上的「认领 / 合作」即可。

"待核实"备注（如 Navicat / Typora 卡片上的小字）：社区推测可能存在对应开源项目，但本轮调研未逐个打开核实，故不给链接。核实通过后才会上链。我们绝不凭推测编造仓库链接。

如何参与？

三步：① 在上面的复刻目标目录里选一个"待认领"的，点「认领 / 合作」（GitHub issue 占位）；② 按卡片里的《10 分钟上手》把仓库立起来；③ 按 SOP 从 S0 走到 S7。parity.md 是你进度的真相源，定期更新，所有人看得见。

需要什么技能？

会用 AI coding 工具、能按 SOP 跑流程，就可以认领大多数目标。深水区（音视频编解码、图形学、编译器）欢迎专家认领对应模块——parity 清单拆到任务卡一级，专家只啃硬骨头也行。

复刻和"逆向工程"是什么关系？

逆向是为功能性复刻服务的前置工具，不是目的。我们用 REA 这类工具搞清"它有什么功能、模块怎么切分"，然后 clean-room 重写。交付物永远是自己写的代码。

为什么不用中心服务器 / 中央 key 池？

中央 key 池集中了泄露面、滥用风险和账单纠纷，是安全和合规的坑。我们的答案：静态站 + GitHub Pages（零服务器），协作靠 GitHub org（零自建平台），算力各跑各的 key，中心只共享 prompts、SOP、评测集与 parity 清单。
